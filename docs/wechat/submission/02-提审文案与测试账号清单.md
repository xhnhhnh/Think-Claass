## 1. 提交审核时逐字可用：功能页说明

小程序有**两条登录路**：**微信一键登录**与**账号密码登录**（正式版都在，账号密码登录不是开发开关）。
但**首次使用无论走哪条都要先绑定一次微信** —— 未绑定的微信号从服务端只能拿到 ticket、拿不到 token，
绑定完才看得到业务页面。所以审核备注里第一句就要把这个说清，否则审核员必然停在登录/绑定页。

### 1.1 直接可粘贴的审核备注

```text
【首次进入请先绑定账号】
本小程序提供两种登录方式，两者共用同一套会话；首次使用两种方式都需要用账号密码完成一次微信绑定，
绑定之后再用微信打开即可一键进入（属正常流程，不是登录失败）。
1) 微信一键登录：点按钮 → 该微信没绑定过时会跳到绑定页；
2) 账号密码登录：在登录页直接选身份 + 填账号密码，同样在这一步完成绑定。

⚠️ 请在「角色」选择器里选对身份（学生 / 家长 / 老师 / 超管）：
服务端按「账号 + 角色」这一对校验密码，角色选错会提示「账号或密码错误」。

教师端账号：thinkclass_teacher ／ 角色：老师 ／ 密码：【待填】
学生端账号：thinkclass_student ／ 角色：学生 ／ 密码：【待填】
管理端账号（可选，用于演示「管理」页）：【待填】 ／ 角色：超管 ／ 密码：【待填】

【功能页路径】
1. 成长总览：绑定学生账号后自动进入。可看到积分、等级、奖状、今日待办。
2. 我的作业：底部第 2 个 tab。点进任一作业 → 选择题作答 → 提交 → 查看批改结果。
3. AI 智学：成长总览页的入口（或底部 tab，视班级功能开关而定）。
   进入后点「生成今日智学」，会得到一份题目与「为什么选它」的理由；可直接作答。
4. 积分商城：底部第 3 个 tab。展示班内虚拟积分可兑换的班级奖励，全程不涉及任何支付。
5. 教师端：用教师账号登录后进入「班级 / 作业 / 智学看板」三个 tab，
   可发布作业、查看全班薄弱知识点、为学生派发练习单。
6. 管理页（管理员 / 超管账号）：底部多一个「管理」tab，一页三卡 ——
   系统概览（教师/学生/班级数、作业数、累计积分、内存与运行时长）、教师账号列表（只读）、
   AI 设置（提供方 / 接口地址 / 模型 / 超时；密钥留空表示不修改，读取时服务端打码）。

【重要说明】
- 本小程序为课堂教学辅助工具，班级与账号均由教师创建和管理，不开放公众自行注册。
- 「积分商城」里的积分是班级内部虚拟积分，由教师在课堂上发放，
  不存在充值、下单、支付、提现等任何交易功能。
- 不采集手机号、位置、通讯录；仅使用微信登录标识（OpenID）用于账号绑定。
```

### 1.2 关键页面的"点哪里 → 看到什么"

| 页面 | 路径 | 审核员会看到 | 预置数据要求 |
| --- | --- | --- | --- |
| 登录 | 打开小程序 | 两种方式：微信一键登录按钮，或直接选「角色 + 账号 + 密码」登录 | 两个测试账号必须可用 |
| 绑定 | 两条登录路首次进入都会到这里 | 需选择身份（学生/家长/老师/超管）并填账号密码 | 角色必须与账号配对（选错 → 401「账号或密码错误」） |

| --- | --- | --- | --- | --- |
| 审核员 · 学生 | `thinkclass_student` | 【待填】 | 学生 | 积分、作业、智学、商城 |
| 审核员 · 教师 | `thinkclass_teacher` | 【待填】 | 教师 | 班级、作业发布、智学看板 |
| 审核员 · 管理（可选，演示「管理」tab） | 【待填】 | 【待填】 | 超管 | 系统概览、教师账号列表、AI 设置 |
| 你自己 · 演示 | 【待填】 | 【待填】 | 教师 | 同教师 |

### 提交前用**审核员视角**走一遍（不要用你自己的号）

- [ ] 用一个**没绑定过任何账号**的微信号扫码进入（新微信号 / 家人的手机）。
- [ ] 确认落在绑定页，**选对角色**后按 1.1 的账号密码绑定成功。
- [ ] 两条登录路各走一遍：微信一键登录，以及登录页的账号密码登录（后者首次同样会完成一次绑定）。
- [ ] 逐页走 1.2 的关键页面，**每一页都有数据**（空数据 = "无法体验功能" = 驳回）。
- [ ] 若有管理/超管测试账号：确认「管理」tab 的系统概览、教师列表、AI 设置三张卡都能打开。
- [ ] 解绑再试一次：`POST /api/wechat/unbind`（同一微信号只能绑一个账号，
      如果审核员的微信已经绑过别的测试账号，必须先解绑）。

> 提醒：服务端按 `账号 + 角色` 这一对共同校验密码（只有整个缺 `role` 字段才会是 400「绑定参数不完整」）。
> **角色选错会得到 401「账号或密码错误」** —— 这是审核员最容易卡住的地方，审核备注里务必写清"先选对身份"。

## 3. 隐私保护指引逐项对照（声明必须与实现一致）

在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」填写。**填了什么，代码里就必须真那么做**；
声明了没实现、或实现了没声明，都是驳回理由。

| 收集项 | 是否收集 | 代码依据 | 指引里怎么写 |
| --- | --- | --- | --- |
| 微信登录标识（OpenID） | **是** | `plugins/wechat` 的 `/api/wechat/login`、`/api/wechat/bind` | 用于账号绑定与登录 |
| 学生姓名 | **是**（由教师录入） | 服务端 **AES-256-CBC 加密存储**（`ENCRYPTION_KEY`，G18 保证无默认值） | 用于班级名单、作业与课堂记录 |
| 照片（作业拍照） | **是（网页端 + 小程序端都已支持）** | 小程序端 `utils/request.ts#upload`（`wx.uploadFile`）+ `pages/student/homework-detail.ts` 选图 → `POST /api/homework/submissions/:id/photos`，字段名 `file` | **要勾选"相册/摄像头"**：用于学生把作业拍照提交给老师批改。不勾 = 声明与实现不符 |
| 设备/日志信息 | 是 | 服务端日志、审计 | 用于排障与安全审计 |
| 手机号 | **否** | 无任何 `getPhoneNumber` 调用 | 不勾 |
| 位置 | **否** | 无 `getLocation` 调用 | 不勾 |
| 通讯录 | **否** | — | 不勾 |

> ⚠️ 这一行是最容易踩坑的地方：**小程序端已经能拍照上传**（v2.2.0 起），所以隐私指引里
> **必须**勾选相册/摄像头，并同时在小程序后台配好 **`uploadFile` 合法域名**。
> 只配 `request` 域名会出现"页面能开、上传必失败"。

## 4. 类目与名称口径一致性检查（审核最顺的状态）

策略见 [05 行动手册阶段 A](../05-action-plan.md)：个人主体选**「工具」**类的子类，
规避教育行业词。**名称、类目、简介、页面文案四者口径必须一致。**

- [ ] 名称：不含"班级/课堂/教学/学校/学生/老师/作业/课程/教育/培训/辅导/考试/成绩/试卷"。
- [ ] 服务类目：`工具` 下的子类，**且后台提示的资质要求为空**。
- [ ] 简介：一句话说明是工具（例：**「记录积分、兑换奖励的小工具」**）。
- [ ] 页面文案：不出现"课程售卖/报名/招生/付费课程"；积分商城文案写成
      **「班级积分兑换」**，不写"商城/购买/下单"。
- [ ] 导航栏标题与登记名称一致 —— 当前 `miniprogram/app.json` 里是 `Think-Class`，
      **定名后需要改这一处**（改完重新上传）。
- [ ] 认证那一项忽略：个人主体不支持微信认证，"未认证不影响版本发布"。
