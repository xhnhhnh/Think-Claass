## 1. 提交审核时逐字可用：功能页说明

小程序**必须先微信登录，再用账号密码绑定业务身份**才能看到任何业务页面（这是刻意的两步设计）。
所以审核备注里第一句就要把这个说清，否则审核员必然停在绑定页。

### 1.1 直接可粘贴的审核备注

```text
【首次进入请先绑定账号】
本小程序需要先绑定已有账号才能体验业务功能（微信登录 → 绑定账号，属正常流程）。

教师端账号：thinkclass_teacher ／ 密码：【待填】
学生端账号：thinkclass_student ／ 密码：【待填】

【功能页路径】
1. 成长总览：绑定学生账号后自动进入。可看到积分、等级、奖状、今日待办。
2. 我的作业：底部第 2 个 tab。点进任一作业 → 选择题作答 → 提交 → 查看批改结果。
3. AI 智学：成长总览页的入口（或底部 tab，视班级功能开关而定）。
   进入后点「生成今日智学」，会得到一份题目与「为什么选它」的理由；可直接作答。
4. 积分商城：底部第 3 个 tab。展示班内虚拟积分可兑换的班级奖励，全程不涉及任何支付。
5. 教师端：用教师账号绑定后进入「班级 / 作业 / 智学看板」三个 tab，
   可发布作业、查看全班薄弱知识点、为学生派发练习单。

【重要说明】
- 本小程序为课堂教学辅助工具，班级与账号均由教师创建和管理，不开放公众自行注册。
- 「积分商城」里的积分是班级内部虚拟积分，由教师在课堂上发放，
  不存在充值、下单、支付、提现等任何交易功能。
- 不采集手机号、位置、通讯录；仅使用微信登录标识（OpenID）用于账号绑定。
```

### 1.2 五个关键页面的"点哪里 → 看到什么"

| 页面 | 路径 | 审核员会看到 | 预置数据要求 |
| --- | --- | --- | --- |
| 登录 | 打开小程序 | 微信授权后自动登录 | — |
| 绑定 | 登录后自动 | 需选择身份（学生/家长/教师）并填账号密码 | 两个测试账号必须可用 |
| 成长总览 | 绑定后首页 | 积分、等级、奖状、宠物、待办 | 学生有 >0 积分、至少 1 张奖状 |
| 我的作业 | tab 2 | 作业列表与状态 | 至少 1 份**已发布**作业、其中 1 份已提交 |
| AI 智学 | 首页入口 | 生成题单 + 每题理由 | 题库至少 5 道题、学生有错题记录 |
| 积分商城 | tab 3 | 班级奖励列表与积分余额 | 至少 3 个上架商品 |
| 智学看板（教师） | 教师 tab 3 | 全班薄弱知识点 + 派单按钮 | 班级学生在该知识点上有错题 |

## 2. 测试账号清单（提交前必须建好并自测）

**规则**：提测账号单独建，**只用于这个用途**；绝不交出 `SUPERADMIN_*`。

| 用途 | 账号 | 密码 | 绑定角色 | 必须能看到 |
| --- | --- | --- | --- | --- |
| 审核员 · 学生 | `thinkclass_student` | 【待填】 | 学生 | 积分、作业、智学、商城 |
| 审核员 · 教师 | `thinkclass_teacher` | 【待填】 | 教师 | 班级、作业发布、智学看板 |
| 你自己 · 演示 | 【待填】 | 【待填】 | 教师 | 同教师 |
| 备选（审核员微信已被占用时换绑） | 【待填】 | 【待填】 | 学生 | 同上 |

### 提交前用**审核员视角**走一遍（不要用你自己的号）

- [ ] 用一个**没绑定过任何账号**的微信号扫码进入（新微信号 / 家人的手机）。
- [ ] 确认落在绑定页，按 1.1 的账号密码绑定成功。
- [ ] 逐页走 1.2 的五个页面，**每一页都有数据**（空数据 = "无法体验功能" = 驳回）。
- [ ] 解绑再试一次：`POST /api/wechat/unbind`（同一微信号只能绑一个账号，
      如果审核员的微信已经绑过别的测试账号，必须先解绑）。

> 提醒：`账号 + 角色` 这一对共同校验密码，绑定页的 role 选错会得到 400「绑定参数不完整」/密码错误。

## 3. 隐私保护指引逐项对照（声明必须与实现一致）

在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」填写。**填了什么，代码里就必须真那么做**；
声明了没实现、或实现了没声明，都是驳回理由。

| 收集项 | 是否收集 | 代码依据 | 指引里怎么写 |
| --- | --- | --- | --- |
| 微信登录标识（OpenID） | **是** | `plugins/wechat` 的 `/api/wechat/login`、`/api/wechat/bind` | 用于账号绑定与登录 |
| 学生姓名 | **是**（由教师录入） | 服务端 **AES-256-CBC 加密存储**（`ENCRYPTION_KEY`，G18 保证无默认值） | 用于班级名单、作业与课堂记录 |
| 照片（作业拍照） | **网页端是，小程序端否** | 小程序端没有 `wx.uploadFile` 流程（见 `miniprogram/README.md` 已知边界） | **小程序隐私指引里不要勾选"相册/摄像头"**，除非确实在小程序里做了上传 |
| 设备/日志信息 | 是 | 服务端日志、审计 | 用于排障与安全审计 |
| 手机号 | **否** | 无任何 `getPhoneNumber` 调用 | 不勾 |
| 位置 | **否** | 无 `getLocation` 调用 | 不勾 |
| 通讯录 | **否** | — | 不勾 |

> ⚠️ 这一行最容易踩坑：**小程序端不收集照片**，但如果你后续补了拍照上传，必须同时回到这份
> 指引里加上，并配好 `uploadFile` 合法域名。

## 4. 类目与名称口径一致性检查（审核最顺的状态）

策略见 [05 行动手册阶段 A](../05-action-plan.md)：个人主体选**「工具」**类的子类，
规避教育行业词。**名称、类目、简介、页面文案四者口径必须一致。**

- [ ] 名称：不含"班级/课堂/教学/学校/学生/老师/作业/课程/教育/培训/辅导/考试/成绩/试卷"。
- [ ] 服务类目：`工具` 下的子类，**且后台提示的资质要求为空**。
- [ ] 简介：一句话说明是工具（例：**「记录积分、兑换奖励的小工具」**）。
- [ ] 页面文案：不出现"课程售卖/报名/招生/付费课程"；积分商城文案写成
      **「班级积分兑换」**，不写"商城/购买/下单"。
- [ ] 导航栏标题与登记名称一致 —— 当前 `miniprogram/app.json` 里是 `Think-Class`，
      **定名后需要改这一处**（改完重新上传）。
- [ ] 认证那一项忽略：个人主体不支持微信认证，"未认证不影响版本发布"。
