# 00 · 竞赛硬约束与材料清单

本文档的目的：把「能不能报、什么时候交、要准备什么材料」这三件事一次说清，
其余技术步骤在 [10](10-deploy-cloudrun.md) / [20](20-deploy-selfhosted.md) / [30](30-release-miniprogram.md)。

> **原文以此为准**：赛事规则、时间、奖项以官方公告为准 ——
> <https://mp.weixin.qq.com/s/vT0ZR13vnHYX2-7TjOk7zw>（2026 微信小程序开发大赛）。
> 本文只做摘要与"对 Think-Class 意味着什么"的落地解读，不替代原文。
> 微信平台的类目/隐私/审核规则以公众平台后台的当前要求为准。

## 1. 硬约束（做不到就直接出局）

| 约束 | 内容 | 对本项目意味着什么 |
| --- | --- | --- |
| 报名与作品提报窗口 | **7 月 17 日 – 10 月 17 日**（2026 微信小程序开发大赛） | 窗口内要完成报名**和**作品提报，不是先报名后慢慢交 |
| 上线状态 | 作品必须**在提报期内通过微信公众平台正式上线** | "体验版""开发版"不算。必须有审核通过 + 已发布的正式版本 |
| 队伍规模 | 单队 **≤ 3 人** | 三个人要同时覆盖前端、后端/部署、材料与审核沟通 |
| 平台 | 微信小程序（微信小程序团队），奖项与 **WAIC**（世界人工智能大会）相关 | 提报材料、演示都要围绕小程序形态，不要指望 Web 站代替 |
| 主体 | 需要一个小程序主体（个人主体可注册小程序，但**要求年满 18 岁**） | 个人主体可选类目更窄，见第 3 节；未成年走监护人主体那条路 |
| **小程序备案** | 2023-09 起，新注册小程序须**完成备案才能上架发布**（工信部要求，与"域名备案"是两回事） | **免不掉**：即使用云托管、没有域名也要做。后台首页那行「备案」就是入口，官方提示"可与代码开发并行，上架发布前完成即可" |

**两条最长、且不由你控制的等待**，都要今天就启动：

1. **小程序备案**：平台初审 1–3 个工作日 → 转省通信管理局审核 → **管局的短信核验有时限**
   （通常 24 小时内要点链接确认，留给**负责人本人**的手机，漏了就退回重来）。整条链路常见
   1–3 周，个人主体也一样。
2. **代码审核**：提交审核到通过通常 1–3 天，可能被驳回整改 —— 预留 3 天，最好 7 天。

倒排时间线时，这两条是骨架；开发与部署都可以和它们并行。

**审核预留 3 天** —— 这是官方提醒里最容易被忽略的一条。审核可能被驳回并要求整改，
一来一回就是两个 3 天。倒排时间线时按"至少留 3 天，最好留 7 天"来算。

## 2. 倒排时间线（建议）

以提报截止日 10 月 17 日为锚点倒推。每一步都留了缓冲，因为后面每一步都可能被打回：

| 时间 | 要做完的事 | 对应文档 |
| --- | --- | --- |
| **今天** | 注册小程序（主体/管理员/邮箱为同一位成年监护人）、**立刻提交小程序备案**、填基础信息与服务类目 | 本文 |
| 尽早 | 后端部署打通（Track A 云托管）：`/api/health` 正常、数据重启不丢 | [10](10-deploy-cloudrun.md) |
| 10.05 前 | 备案号下来（若被管局退回，立刻改材料重提，留出第二次的时间） | 微信公众平台 |
| 10.10 前 | 小程序代码上传 → 体验版 → 真机走通关键流程（微信登录、绑定账号、作业提交） | [30](30-release-miniprogram.md) |
| 10.12 前 | 后端已能被小程序访问（`callContainer` 通、`/api/health` 正常、数据重启不丢） | [10](10-deploy-cloudrun.md) / [20](20-deploy-selfhosted.md) |
| 10.14 前 | **提交审核**（预留 3 天）：类目、隐私保护指引、截图、功能页说明、测试账号就绪 | [30](30-release-miniprogram.md) |
| 审核通过后当天 | **发布**（点"发布"才算正式上线；备案未完成时发布不了） | [30](30-release-miniprogram.md) |
| 10.17 前 | 提报：确认作品处于正式上线状态，提交参赛材料 | 官方公告 |

> 两个"不由你控制"的等待：**小程序备案**（管局审核 + 限时短信核验，常见 1–3 周）与**代码审核**
> （1–3 天，可能驳回）。它们和开发可以并行，但**不能压缩**，所以今天就要把它们推出去。
> 域名备案只有 Track B 才需要；小程序备案 Track A/B 都要。

## 3. 需要准备的材料

### 3.1 主体资质

| 主体类型 | 能做什么 | 注意 |
| --- | --- | --- |
| 个人 | 可以注册小程序、可以选部分类目 | **官方要求「个人 18 岁以上有国内身份信息的微信实名用户」**（[小程序接入指南](https://developers.weixin.qq.com/miniprogram/introduction/index.html)）；可选类目少于企业主体，**教育类类目基本对个人关闭** |
| 企业 / 个体工商户 | 类目最全，可开通支付等能力 | 需要营业执照；认证可能产生费用，以公众平台为准 |
| 事业单位 / 学校 | 教育类目最顺 | 需要办学资质类文件 |

> **未成年（未满 18 岁）参赛者的标准做法**：让**监护人（父母）**做主体与管理员，自己作为**项目成员**
> 参与开发。官方文档写明「个人主体小程序最多可绑定 **15 个项目成员**，15 个体验成员」，添加入口是
> 小程序后台「用户身份 → 成员管理 → 添加成员」（[接入指南](https://developers.weixin.qq.com/miniprogram/introduction/index.html)）。
> 分工：**家长**负责扫码登录、绑定手机号、提交审核、点发布；**你**负责写代码、部署、上传代码。
> 切勿购买、借用他人身份或购买现成小程序账号 —— 这类账号随时可能被原主体找回，且属于违规。

**Think-Class 是课堂教学工具**，是否被判定为"教育"类目，取决于你在小程序里**怎么描述自己**，
而不是代码里有什么功能。这是本清单里最关键的一条：

- **教育类类目普遍要求《民办学校办学许可证》等资质**（不同子类目要求不同，以公众平台类目选择页的提示为准）。
  没有资质时，选教育类目 = 审核必然驳回。
- **没有资质时的做法**：
  1. 服务类目选「**工具**」下的合适子类（如效率/教育辅助中不需资质的项，以后台实际可选列表为准）；
  2. 小程序名称、简介、页面文案、审核备注里**避免出现"培训""课程""售卖""报名""招生""付费课程"**这类表述 ——
     它们会把审核引向教育培训类目；
  3. 不要在小程序里出现任何付费/售卖入口（本项目的"积分商城"是班内虚拟积分，不是钱，
     但文案上要让人一眼看出不是交易，例如写「班级积分兑换」，不要写"商城/购买/下单"）；
  4. 如果确实需要教育类目，就在提报前把资质办下来 —— 这条没有绕过的方法。

### 3.2 小程序基本信息

- **名称**：与"工具"定位一致，别带"培训/课程"。
  **还要避开教育行业词**：班级、课堂、教学、学校、学生、老师、作业、课程、教育、培训、辅导、考试、
  成绩、试卷。实测：名称填「理想中的班级」会被判定「可能涉及特定行业领域」，要求提供《商标注册证》、
  教育行业法定许可或备案证明 —— 个人主体拿不出这些，等于必然驳回。
  安全候选：**积分小芽 / 小芽积分 / 绿芽积分 / 成长积分助手 / 积分口袋**。
  名称的修改次数很有限（个人主体通常一年 2 次，以后台提示为准），别拿雷词反复试。
- **头像**：可以直接用仓库里生成好的品牌图形
  [`docs/wechat/assets/miniprogram-avatar-1024.png`](assets/miniprogram-avatar-1024.png)
  （同目录有 144×144 版本），来自 `src/lib/brandIcon.ts` 的双叶标记，不涉版权。
- **简介**：一句话说清"工具"，例如**「记录积分、兑换奖励的小工具」**；不要写"提供在线课程"，
  也不要出现班级/学生/老师/作业等词。
- **服务类目**：按 3.1 的策略选，选完确认后台提示的资质要求为空。
- **口径一致**：名称像工具、类目是工具、简介是工具 —— 三者一致，审核最顺。功能里当然可以有
  班级、积分、宠物，那是功能层面的事，与名称的行业判定无关。

### 3.3 隐私保护指引（必须做，且必须与事实一致）

在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」里填写，**审核会逐项核对**。
Think-Class 实际会收集/处理的信息，按用途对照填写：

| 收集项 | 本项目为什么需要 | 说明 |
| --- | --- | --- |
| 微信登录标识（OpenID 等） | 学生/教师用微信登录并绑定账号 | 由 `plugins/wechat` 的 `/api/wechat/login` 处理 |
| 学生姓名 | 教师在班级里录入学生，用于作业与课堂记录 | **加密存储**（`ENCRYPTION_KEY`），见 [40](40-troubleshooting.md) |
| 照片（作业拍照） | 学生上传作业照片给老师批改 | 存在 `uploads/`，应用自己提供访问 |
| 设备/日志信息 | 排障与安全审计 | 服务端日志 |

要点：

- 指引里声明了什么，代码里就必须真这么做；**声明了却没实现**（或反之）都是驳回理由。
- 学生是未成年人：材料里要写清"由教师/学校在知情前提下录入并管理"，不要宣称面向未成年人自主注册。
- 本项目**不做**手机号采集、不做位置采集、不做通讯录 —— 指引里不要勾选这些，勾了就要有能力解释用途。

### 3.4 提报/审核材料

- 小程序截图（关键页面：登录、班级/学生、作业列表、拍照上传、批改结果）。
- **功能页说明**：审核员看不到你的服务器，说明里要写清"哪个入口、点几下、能看到什么"。
- **测试账号**：本项目需要登录才能看到任何业务页面（登录是强制的）。
  而且小程序的登录是**两步**：审核员的微信先落在绑定页，要用你给的账号密码完成绑定
  （见 [30 文档第 0.3 节](30-release-miniprogram.md#03-登录方式先微信再绑定账号)）。
  所以审核备注里要写清"首次进入请用以下账号密码绑定"，并给出可用的教师/学生账号与密码。
  没有测试账号 = 审核员进不去 = 直接驳回。
  > 提测账号请单独建、且只用在这个用途上；`SUPERADMIN_*` 不要交出去。
- 需要的资质文件（若所选类目要求）。

## 4. 提报前的检查清单

按顺序打勾，任一项没过都不要点"提交审核"：

- [ ] 后端已上线，`curl https://<域名>/api/health` 返回 200 且 `success: true`
      （云托管路线：`/api/health` 在容器健康检查里也是绿的）。
- [ ] 小程序「服务器域名」已配置（Track B），或已改用 `wx.cloud.callContainer`（Track A，无需配置域名）。
- [ ] 真机（不只是开发者工具）走通：微信登录 → 绑定账号 → 打开作业 → 提交 → 教师端能看到。
      （拍照上传目前是 Web 端流程，小程序里没有上传代码；如果要把它算作提报功能，先补上并配好 `uploadFile` 域名。）
- [ ] 重启一次后端，学生姓名仍**可读**（不是乱码）—— 说明 `ENCRYPTION_KEY` 与数据都在持久存储上。
- [ ] 隐私保护指引已提交，且与第 3.3 节的表一致。
- [ ] 服务类目已选定，后台没有"需补充资质"的提示。
- [ ] 审核备注里写好了功能页说明 + 测试账号密码。
- [ ] 距离提报截止至少还有 3 天（给驳回整改留时间）。

## 5. 常见驳回原因（与本项目相关的）

| 驳回理由 | 通常的根因 | 处理 |
| --- | --- | --- |
| 类目与内容不符 | 选了工具类目，但页面文案是"课程/培训" | 改文案，或补教育类资质 |
| 缺少资质 | 教育类子类目要求办学许可证 | 换类目（工具）或补资质 |
| 隐私指引与实际不符 | 声明了未收集的信息，或收集了未声明的信息 | 对着第 3.3 节逐项核对 |
| 无法体验功能 | 没有测试账号，或账号登录后是空数据 | 提供测试账号，并预置一个班 + 一次作业 + 一条拍照提交 |
| 服务不可用 | 证书链不完整 / 域名未备案 / 容器冷启动超时 | 见 [40-troubleshooting.md](40-troubleshooting.md) |
